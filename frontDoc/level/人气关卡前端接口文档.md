# 人气关卡 - 前端接口文档

## 一、概述

本次改造新增 2 个接口，配合已有的「提交作答」接口，前端可完成完整流程：

```
人气关卡列表  →  关卡详情（选选项）  →  提交作答（出报告）
GET /level/hot   GET /level/{id}        POST /level/submit（复用）
```

| 接口 | 方法 | 是否需登录 | 本次改动 |
|------|------|-----------|---------|
| `/api/level/hot` | GET | 否 | **新增** |
| `/api/level/{id}` | GET | 否 | **新增** |
| `/api/level/submit` | POST | 是 | 复用（已有） |

## 二、通用约定

- **Base URL**：`http://{host}:8101/api`（后端 `context-path` 为 `/api`）
- **统一响应体**：所有接口返回 `BaseResponse<T>`
- **`id` 字段是字符串**：后端 `Long` 全局序列化为 `string`（防 JS 精度丢失），前端拿到的 `id` 都是 string，提交时也用 string 传回
- **错误码**：

| code | 含义 |
|------|------|
| 0 | 成功 |
| 40000 | 参数错误 |
| 40100 | 未登录 |
| 40300 | 禁止访问 |
| 40400 | 数据不存在 |
| 50000 | 系统异常 |

- **登录态**：基于 Session，浏览器同域下 axios 默认携带 cookie，无需手动加 token。

```json
// BaseResponse 结构
{
  "code": 0,
  "data": { ... },
  "message": "ok"
}
```

## 三、接口详情

### 1. 人气关卡列表

浏览热门关卡，按作答次数降序。**无需登录**。

**请求**

```
GET /api/level/hot?limit=10&direction=Java后端开发
```

Query 参数：

| 参数 | 类型 | 必填 | 默认 | 说明 |
|------|------|------|------|------|
| limit | number | 否 | 10 | 返回数量（1~50） |
| direction | string | 否 | 无 | 学习方向筛选，如 `Java后端开发`、`前端开发`、`软件测试`；不传则返回全部 |

**响应示例**

```json
{
  "code": 0,
  "message": "ok",
  "data": [
    {
      "id": "1001",
      "levelName": "电商秒杀库存扣减",
      "levelDesc": "设计一个高并发秒杀场景下的库存扣减方案，要求不超卖、响应快、可扩展…",
      "difficulty": "中等",
      "targetSalary": 18000,
      "direction": "Java后端开发",
      "playCount": 342,
      "priority": 999
    },
    {
      "id": "1002",
      "levelName": "前端首屏性能优化",
      "levelDesc": "针对首屏加载慢的问题给出优化方案…",
      "difficulty": "简单",
      "targetSalary": 12000,
      "direction": "前端开发",
      "playCount": 201,
      "priority": 99
    }
  ]
}
```

`data` 为 `HotLevelVO[]`，字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 关卡 id，点进详情用 |
| levelName | string | 关卡名称 |
| levelDesc | string | 需求描述 |
| difficulty | string | 难度：`简单` / `中等` / `困难` |
| targetSalary | number | 目标薪资（元/月） |
| direction | string | 学习方向 |
| playCount | number | 作答次数，越大越靠前 |
| priority | number | 优先级：0 普通 / 99 推荐 / 999 精选 / 9999 置顶 |

### 2. 关卡详情（作答页）

获取完整题目（**选项不含答案**），用于作答页展示。**无需登录**。

**请求**

```
GET /api/level/{id}
```

Path 参数：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | string | 是 | 关卡 id（来自人气列表的 `id`） |

**响应示例**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": "1001",
    "levelName": "电商秒杀库存扣减",
    "levelDesc": "设计一个高并发秒杀场景下的库存扣减方案…",
    "options": ["Redis 预扣减", "数据库乐观锁", "直接扣数据库", "消息队列削峰"],
    "difficulty": "中等",
    "targetSalary": 18000
  }
}
```

`data` 为 `LevelVO`，字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 关卡 id |
| levelName | string | 关卡名称 |
| levelDesc | string | 需求描述 |
| options | string[] | 选项名称列表（**不含答案**，答案只在后端） |
| difficulty | string | 难度 |
| targetSalary | number | 目标薪资 |

**错误**：关卡不存在返回 `code = 40400`。

### 3. 提交作答（复用）

用户选完选项后提交，出报告并更新薪资。**需登录**。

**请求**

```
POST /api/level/submit
Content-Type: application/json
```

请求体：

```json
{
  "levelId": "1001",
  "userOptions": ["Redis 预扣减", "消息队列削峰"]
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| levelId | string | 是 | 关卡 id |
| userOptions | string[] | 是 | 用户选择的选项名称（非空） |

**响应示例**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "levelId": "1001",
    "score": 80,
    "comment": "表现不错，建议涨薪",
    "salaryChange": 2000,
    "suggest": "建议投递企鹅大王",
    "reason": "选对了核心方案，但遗漏了降级细节",
    "trueOptions": ["Redis 预扣减", "消息队列削峰", "数据库乐观锁"],
    "standardAnswer": "本关卡标准方案是……（Markdown 文本）",
    "newSalary": 12000
  }
}
```

`data` 为 `ReportVO`，字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| levelId | string | 关卡 id |
| score | number | 得分（0~100） |
| comment | string | 评价 |
| salaryChange | number | 薪资变化（正加薪 / 负减薪） |
| suggest | string | 公司投递建议 |
| reason | string | 评分原因 |
| trueOptions | string[] | 正确答案 |
| standardAnswer | string | 标准答案解析（Markdown） |
| newSalary | number | 调整后的薪资 |

## 四、TypeScript 类型定义

```typescript
// 统一响应体
interface BaseResponse<T> {
  code: number;
  data: T;
  message: string;
}

// 人气关卡列表项
interface HotLevelVO {
  id: string;           // 关卡 id
  levelName: string;    // 关卡名称
  levelDesc: string;    // 需求描述
  difficulty: string;   // '简单' | '中等' | '困难'
  targetSalary: number; // 目标薪资
  direction: string;    // 学习方向
  playCount: number;    // 作答次数（热度）
  priority: number;     // 优先级
}

// 关卡详情
interface LevelVO {
  id: string;
  levelName: string;
  levelDesc: string;
  options: string[];    // 选项名称（不含答案）
  difficulty: string;
  targetSalary: number;
}

// 提交请求
interface LevelSubmitRequest {
  levelId: string;      // 注意：string，与列表/详情返回的 id 类型一致
  userOptions: string[];
}

// 报告
interface ReportVO {
  levelId: string;
  score: number;
  comment: string;
  salaryChange: number;
  suggest: string;
  reason: string;
  trueOptions: string[];
  standardAnswer: string;
  newSalary: number;
}
```

## 五、axios 调用示例

```typescript
import axios from 'axios';

const http = axios.create({
  baseURL: 'http://localhost:8101/api',
  withCredentials: true,   // 携带 session cookie（提交作答需登录）
});

// 1. 人气关卡列表
const listHot = async () => {
  const { data } = await http.get<BaseResponse<HotLevelVO[]>>('/level/hot', {
    params: { limit: 10, direction: 'Java后端开发' },
  });
  return data.data;
};

// 2. 关卡详情
const getDetail = async (id: string) => {
  const { data } = await http.get<BaseResponse<LevelVO>>(`/level/${id}`);
  return data.data;
};

// 3. 提交作答
const submit = async (levelId: string, userOptions: string[]) => {
  const { data } = await http.post<BaseResponse<ReportVO>>('/level/submit', {
    levelId,
    userOptions,
  });
  return data.data;
};
```

## 六、完整流程串联（伪代码）

```typescript
// 1. 展示人气关卡列表
const hotList = await listHot();

// 2. 用户点击某个关卡 → 拉详情展示选项
const detail = await getDetail(hotList[0].id);

// 3. 用户勾选若干选项后提交
const report = await submit(detail.id, ['Redis 预扣减', '消息队列削峰']);

// 4. 展示报告 + 新薪资
console.log(report.score, report.newSalary);
```

## 七、注意事项

- **答案不在前端**：`options` 只有选项名，正确答案只存后端，前端提交时只需回传用户选的 `optionName`，后端自己判卷。
- **id 一律按 string 处理**：不要在前端把 `id` 转成 number（会精度丢失），列表 → 详情 → 提交全程用 string。
- **`submit` 需登录**：未登录返回 `code = 40100`，前端需引导用户先登录。
