# 用户接口

## 1. 注册 `POST /user/register`

注册支持 **两种方式**：密码注册、邮箱注册。通过请求体中的 `registerType` 字段区分。

> ⚠️ 前端只需传自己注册方式对应的参数，另一种方式的参数**不用传**（后端会忽略）。

### 1.1 通用参数

| 字段          | 类型   | 必填 | 说明                                             |
| ------------- | ------ | ---- | ------------------------------------------------ |
| `registerType` | string | 否   | 注册方式：`password` / `email`。**不传默认 `password`** |
| `direction` | string | 否   | 学习方向标签，决定后续出题方向。推荐值：`Java后端开发` / `前端开发` / `Go开发` / `Agent开发`，可自定义；不传默认 `全栈开发` |

> `direction` 是注册时用户选择的**学习方向标签**，会存到用户表、后续生成关卡时作为检索和出题的方向。前端建议做成「下拉框（上面 4 个推荐值）+ 自定义输入」。

### 1.2 密码注册（`registerType = "password"`）

| 字段            | 类型   | 必填 | 说明                                                         |
| --------------- | ------ | ---- | ------------------------------------------------------------ |
| `username`      | string | 是   | 用户名，长度 ≥ 4，不能包含特殊字符                            |
| `password`      | string | 是   | 密码，长度 ≥ 8                                               |
| `checkPassword` | string | 是   | 确认密码，必须与 `password` 一致                             |
| `nickname`      | string | 否   | 昵称，不传默认取 `username`                                  |
| `email` / `code` | -     | 否   | 邮箱注册的字段，密码注册时**忽略**，不用传                    |

**请求示例**

```json
{
  "registerType": "password",
  "username": "xiaoHua",
  "password": "12345678",
  "checkPassword": "12345678",
  "nickname": "小花",
  "direction": "Java后端开发"
}
```

**成功响应**

```json
{
  "code": 0,
  "data": "1",        // 新用户 id（字符串）
  "message": "ok"
}
```

**失败响应（`code=40000`，部分可能提示）**

```json
{
  "code": 40000,
  "data": null,
  "message": "两次输入的密码不一致"
}
```

可能出现的失败提示：`参数为空`、`用户名过短`、`用户密码过短`、`用户名不能包含特殊字符`、`两次输入的密码不一致`、`用户名已存在`。

### 1.3 邮箱注册（`registerType = "email"`）

| 字段       | 类型   | 必填 | 说明                                                         |
| ---------- | ------ | ---- | ------------------------------------------------------------ |
| `email`    | string | 是   | 邮箱，格式必须包含 `@`，且不能重复注册                       |
| `code`     | string | 是   | 邮箱验证码（由"发送验证码"接口下发，见下方注意事项）          |
| `password` | string | 是   | 密码，长度 ≥ 8                                               |
| 其余字段   | -      | 否   | `username` / `checkPassword` / `nickname` 邮箱注册时**忽略** |

**请求示例**

```json
{
  "registerType": "email",
  "email": "xiaoHua@qq.com",
  "code": "123456",
  "password": "12345678",
  "direction": "前端开发"
}
```

**成功响应**（注册后 `username`、`nickname` 自动取邮箱 @ 前缀）

```json
{
  "code": 0,
  "data": "2",
  "message": "ok"
}
```

**失败响应（`code=40000`）**

| 提示                              | 触发场景                         |
| --------------------------------- | -------------------------------- |
| `邮箱、验证码或密码不能为空`       | 三者任一为空                     |
| `邮箱格式不正确`                   | email 不含 `@`                   |
| `密码长度不能小于8位`              | 密码过短                         |
| `验证码已过期，请重新获取`         | Redis 中没有验证码（过期/未发送）|
| `验证码错误`                       | 验证码不匹配                     |
| `该邮箱已注册`                     | 邮箱已存在                       |
| `不支持的注册方式: xxx`            | `registerType` 不是 password/email |

### 1.4 发送邮箱验证码 `POST /user/sendCode`

邮箱注册前，先调用本接口获取验证码（5 分钟有效），再带 `code` 调 `/user/register`。

| 字段    | 类型   | 必填 | 说明                        |
| ------- | ------ | ---- | --------------------------- |
| `email` | string | 是   | 接收验证码的邮箱，需包含 `@` |

**请求示例**

```json
{
  "email": "xiaoHua@qq.com"
}
```

**成功响应**

```json
{
  "code": 0,
  "data": true,
  "message": "ok"
}
```

**失败响应**：`{"code":40000,"message":"邮箱格式不正确"}`。

> 验证码 5 分钟有效，重复发送会覆盖旧验证码。开发环境未配置 SMTP 时，验证码会打印在服务端日志中，联调时可从日志取。

### 1.5 注意事项

- 邮箱注册完整流程：**先调 `POST /user/sendCode` 获取验证码 → 再调 `POST /user/register`（`registerType=email`）注册**。
- 生产环境需在 `application.yml` 配置真实的 SMTP 账号，否则邮件发送失败（dev 会降级为日志输出验证码）。
- 邮箱注册时需要 Redis 服务可用；Redis 不可用时会报连接错误。
- 无论哪种方式，成功后返回新用户 id，前端可再调 `/user/current` 拉取完整用户信息（注册接口**不自动登录**）。

## 2. 登录 `POST /user/login`

| 字段       | 类型   | 必填 | 说明             |
| ---------- | ------ | ---- | ---------------- |
| `username` | string | 是   | 用户名           |
| `password` | string | 是   | 密码             |

**请求示例**

```json
{
  "username": "xiaoHua",
  "password": "12345678"
}
```

**成功响应**（返回脱敏用户信息）

```json
{
  "code": 0,
  "data": {
    "id": "1",
    "username": "xiaoHua",
    "nickname": "小花",
    "avatar": "https://img.icons8.com/color/96/000000/user-male-circle--v1.png",
    "userRole": "user",
    "salary": 10000,
    "direction": "Java后端开发",
    "createTime": "2026-08-25T10:00:00"
  },
  "message": "ok"
}
```

**失败响应**：`{"code":40000,"message":"用户不存在或密码错误"}` 等。

登录成功后 Session 写入 Cookie，后续请求自动携带，无需前端处理 token。

---

## 3. 获取当前登录用户 `GET /user/current`

无请求参数（依赖登录态）。

**成功响应**：同登录接口的 `data`（UserVO）。

**未登录响应**

```json
{
  "code": 40100,
  "data": null,
  "message": "未登录"
}
```

> 前端可通过该接口判断登录态：`code === 0` 表示已登录；`code === 40100` 表示未登录，跳转登录页。

---

## 4. 注销 `POST /user/logout`

无请求参数（依赖登录态）。

**成功响应**

```json
{
  "code": 0,
  "data": true,
  "message": "ok"
}
```

**未登录响应**：`{"code":40000,"message":"未登录"}`（该接口业务错误统一返回 40000）。
