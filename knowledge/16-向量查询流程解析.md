# 向量查询全流程解析（小白版）

> 目标：把「用户输入一个方向 → 从向量库查到相关知识 → 塞给大模型出题」这条链路，一行行拆开讲清楚，并标注每个方法来自哪（Java 标准库 / Spring / LangChain4j / 通用概念）。

---

## 一、先看全景：一次出题请求经过哪里

```
用户调用  POST /level/generate?salary=10000&direction=Java后端开发
   │
   ▼
LevelController.generateLevel()           ← HTTP 入口
   │
   ▼
LevelServiceImpl.generateLevel()
   │  ① knowledge = knowledgeService.retrieve(directionText)   ← 向量检索（本文主角）
   │  ② levelAiService.generateLevel(salary, direction, knowledge)  ← 大模型出题
   ▼
返回 LevelVO（关卡）
```

本文只讲 **① 向量检索**这一环，它是 RAG 的「R」（Retrieval，检索）。完整 RAG 概念见 `14-RAG检索增强出题改造.md`。

## 二、入口：generateLevel 怎么调用检索

`LevelServiceImpl.java:59-65`：

```java
public LevelVO generateLevel(int salary, String direction) {
    // direction 为空时给个默认值（StrUtil 是 Hutool 工具库，isBlank 判断是否空字符串）

```

## 三、核心：retrieve 方法逐行拆解

`KnowledgeService.java:37-58`（完整代码）：

```java
public String retrieve(String query) {
    // 1. 把查询也向量化
    Embedding queryEmbedding = embeddingModel.embed(query).content();

    // 2. 构造检索请求
    EmbeddingSearchRequest request = EmbeddingSearchRequest.builder()
            .queryEmbedding(queryEmbedding)
            .maxResults(3)
            .minScore(0.2)
            .build();

    // 3. 从向量库搜索
    EmbeddingStore<TextSegment> store = ragIndexService.getEmbeddingStore();
    EmbeddingSearchResult<TextSegment> result = store.search(request);

    // 4. 取命中片段，拼成一段文本
    List<EmbeddingMatch<TextSegment>> matches = result.matches();
    if (matches.isEmpty()) {
        return "";
    }
    return matches.stream()
            .map(match -> match.embedded().text())
            .collect(Collectors.joining("\n\n---\n\n"));
}
```

下面分 4 步讲。

### 第 1 步：把查询「向量化」

```java
Embedding queryEmbedding = embeddingModel.embed(query).content();
```

- `embeddingModel`：之前 `RagConfig` 里创建的 `QwenEmbeddingModel`（通义千问的向量化模型）。
- `embed(query)`：把字符串 `query`（如 `"Java后端开发"`）变成**向量**（一串数字）。
- `.content()`：因为 `embed()` 返回的是一个「包装盒」`Response<Embedding>`，里面除了向量还可能带元信息；`.content()` 把盒子里的真正内容 `Embedding` 取出来。

**为什么要向量化？** 大模型和向量库都「看不懂中文，只认数字」。要比较「查询」和「知识库里的片段」像不像，必须先把两边都变成数字（向量），才能用数学算距离。这就是 embedding 模型的职责（详见 `14` 文档）。

### 第 2 步：构造检索请求

```java
EmbeddingSearchRequest request = EmbeddingSearchRequest.builder()
        .queryEmbedding(queryEmbedding)   // 用哪个向量去搜
        .maxResults(3)                    // 最多返回 3 条最像的
        .minScore(0.2)                    // 相似度低于 0.2 的不要
        .build();
```

这是 **builder（建造者）模式**：不直接 `new`，而是 `.builder()` 一路 `.xxx()` 链式设置，最后 `.build()` 生成对象。好处是参数多时写法清晰、可读性强。

三个参数：

| 参数 | 含义 | 通俗讲 |
|------|------|--------|
| `queryEmbedding` | 查询的向量 | 拿「问题」去比 |
| `maxResults(3)` | 返回几条 | 只取最像的前 3 条 |
| `minScore(0.2)` | 相似度门槛 | 低于 0.2 的直接丢弃（宁缺毋滥） |

### 第 3 步：从向量库搜索

```java
EmbeddingStore<TextSegment> store = ragIndexService.getEmbeddingStore();
EmbeddingSearchResult<TextSegment> result = store.search(request);
```

- `ragIndexService.getEmbeddingStore()`：从 `RagIndexService` 拿到「当前生效的向量库」（存着所有知识片段的向量 + 原文）。为什么要通过它拿而不是直接注入？因为 rebuild 重建时 store 会被换成新的，通过这个方法拿到的永远是「最新」的那个。
- `store.search(request)`：核心动作——**在向量库里找出和查询向量最相似的片段**。这一步是真正「算距离」的地方。

`<TextSegment>` 是**泛型**：表示这个向量库存的是 `TextSegment` 类型（一段文本）。泛型就是「告诉编译器里面装的是哪种东西」，保证类型安全。

### 第 4 步：取命中片段，拼成文本

```java
List<EmbeddingMatch<TextSegment>> matches = result.matches();
if (matches.isEmpty()) {
    return "";
}
return matches.stream()
        .map(match -> match.embedded().text())
        .collect(Collectors.joining("\n\n---\n\n"));
```

- `result.matches()`：搜索结果里的「命中列表」，每一项是一个 `EmbeddingMatch`（一条匹配结果）。
- `match.embedded()`：取出这条匹配里存的原文片段（`TextSegment`）。
- `.text()`：取这个片段的纯文本内容。
- `.map(...)`：把每条 `EmbeddingMatch` 变成它的文本。
- `.collect(Collectors.joining("分隔符"))`：把所有文本用 `\n\n---\n\n`（换行 + 分隔线）拼成一个字符串。

如果一条都没命中（`matches.isEmpty()`），返回空字符串 `""`，表示「没检索到相关知识」。

## 四、数据一步步长什么样

假设 `query = "Java后端开发"`：

| 步骤 | 变量 | 长什么样（示意） |
|------|------|-----------------|
| 输入 | `query` | `"Java后端开发"`（一个字符串） |
| 向量化 | `queryEmbedding` | `Embedding{ vector = [0.012, -0.34, 0.88, ...] }`（1536 个 float） |
| 搜索 | `result.matches()` | 3 个 `EmbeddingMatch`，每个带 `score`（相似度）+ `embedded`（原文片段） |
| 取原文 | `match.embedded().text()` | `"Redis 缓存穿透：查询一个不存在的 key..."` |
| 拼接 | `knowledge` | 3 段原文，中间用 `---` 分隔的一大段文本 |

最终这个 `knowledge` 字符串，就是塞进大模型提示词里的「参考资料」。

## 五、这些方法来自哪（Java / Spring / LangChain4j / 通用）

| 代码 | 来自 | 说明 |
|------|------|------|
| `List`、`String` | **Java 标准库** | Java 语言自带，其他语言都有等价物 |
| `matches.stream()`、`.map()`、`.collect()` | **Java 标准库**（Stream API） | Java 8 引入的流式处理，是 Java 特有语法；概念上等价 Python 的列表推导 |
| `Collectors.joining()` | **Java 标准库** | 字符串拼接工具，等价 Python 的 `"分隔符".join(list)` |
| `StrUtil.isBlank()` | **Hutool 工具库** | 第三方 Java 库，判空用 |
| `@Service`、`@Resource`、`@Value` | **Spring 框架** | Java 生态的依赖注入注解 |
| `embeddingModel.embed()` | **LangChain4j** | 向量化方法，概念通用（Python 的 LangChain 也有 embed） |
| `Embedding`、`EmbeddingSearchRequest`、`EmbeddingSearchResult`、`EmbeddingMatch`、`TextSegment` | **LangChain4j** | 这些类名是 LangChain4j 特有，但背后概念（向量、检索请求、命中结果、文本片段）所有 RAG 框架都有 |
| `EmbeddingStore` | **LangChain4j** | 向量库的统一接口，底层可以是内存/Milvus/pgvector 任意实现 |
| `store.search()` | **LangChain4j** | 相似度检索，概念通用（本质是「算向量距离取 top-K」） |
| builder 模式（`.builder()...build()`） | **通用设计模式** | 不是 Java 独有，很多语言都有建造者模式 |

**一句话总结「哪些是通用的」**：Java 标准库的语法和类名是 Java 特有，但**背后的思想**（向量化、算相似度、取 top-K、字符串拼接）是所有语言、所有 RAG 框架都一样的。你学会了这套思路，换 Python/LangChain 只是换层皮。

## 六、几个小白容易懵的点

### 1. `Response.content()` 是干嘛的？

LangChain4j 很多方法不直接返回结果，而是返回 `Response<T>`（一个「信封」），里面除了结果还可能有 token 用量、结束原因等元信息。`.content()` 就是从信封里掏出真正的结果 `T`。你只需要记住：**`.content()` = 拿真正的内容**。

### 2. builder 模式为什么不用 `new`？

`new EmbeddingSearchRequest(...)` 参数一多就记不住顺序、可读性差。builder 模式用 `.queryEmbedding(...).maxResults(...).minScore(...)` 链式写，每个参数名都清清楚楚，`.build()` 时才真正创建对象。这是 Java（和很多语言）里很常见的写法。

### 3. 泛型 `<TextSegment>` 是什么？

`EmbeddingStore<TextSegment>` 里的 `<TextSegment>` 表示「这个向量库里存的元素类型是 TextSegment」。泛型的目的是让编译器帮你检查类型，避免把错误类型塞进去。你把它读作「存 TextSegment 的向量库」就行。

### 4. 为什么查询和知识库必须用同一个 embedding 模型？

向量化模型就像一个「翻译规则」，把文字映射到数字空间。如果知识库用 A 模型、查询用 B 模型，两边映射到的「空间」不一样，算出来的距离就毫无意义（相当于用厘米和英寸比长度，单位都没统一）。所以必须同一个模型。

---

## 七、一句话总结

> **检索 = 把查询向量化 → 在向量库里算相似度 → 取最像的前几条 → 把原文拼成一段字符串**，这个字符串就是喂给大模型的「参考资料」。全程只有 `store.search()` 是 LangChain4j 的检索魔法，其余都是普通 Java。
