# 人气关卡模块改造

## 背景

此前关卡只能通过 `POST /api/level/generate` 由 AI 现场生成，用户无法直接浏览和作答「热门关卡」。本次新增人气关卡能力：按 `UserLevel` 表的作答次数统计最热门的关卡，用户点进去即可作答出报告。

设计上沿用「关卡池」思路（见 [11-人气关卡模块.md](11-人气关卡模块.md)）：AI 生成、预置兜底、人气推荐统一到 `Level` 表，复用已有的 `priority`、`direction` 字段，**不改表结构**。

## 关键代码

### 1. 人气统计 SQL（LevelMapper.xml）

用子查询统计作答次数，避免 `ONLY_FULL_GROUP_BY` 坑；`priority` 作为作答次数相同时的次级排序权重：

```xml
<select id="selectHotLevels" resultMap="HotLevelResultMap">
    SELECT l.id, l.levelName, l.levelDesc, l.difficulty, l.targetSalary,
           l.direction, l.priority,
           (SELECT COUNT(*) FROM user_level ul
             WHERE ul.levelId = l.id AND ul.isDelete = 0) AS playCount
    FROM level l
    WHERE l.isDelete = 0
    <if test="direction != null and direction != ''">
        AND l.direction = #{direction}
    </if>
    ORDER BY playCount DESC, l.priority DESC, l.id DESC
    LIMIT #{limit}
</select>
```

### 2. Service 实现（LevelServiceImpl）

```java
@Override
public List<HotLevelVO> listHotLevels(int limit, String direction) {
    int safeLimit = Math.max(1, Math.min(limit, 50));
    return baseMapper.selectHotLevels(safeLimit, direction);
}

@Override
public LevelVO getLevelDetail(Long levelId) {
    Level level = this.getById(levelId);
    if (level == null) {
        throw new BusinessException(ErrorCode.NOT_FOUND_ERROR, "关卡不存在");
    }
    List<LevelOption> levelOptions;
    try {
        levelOptions = objectMapper.readValue(level.getOptions(),
                new TypeReference<List<LevelOption>>() {});
    } catch (JsonProcessingException e) {
        throw new BusinessException(ErrorCode.SYSTEM_ERROR, "关卡选项解析失败");
    }
    return buildLevelVO(level.getId(), level.getLevelName(), level.getLevelDesc(),
            levelOptions, level.getDifficulty(), level.getTargetSalary());
}
```

### 3. 抽取 buildLevelVO（复用脱敏逻辑）

`generateLevel` 与 `getLevelDetail` 都需把「含 `trueAnswer` 的选项」脱敏成「只含 `optionName` 的选项」，抽成私有方法消除重复：

```java
private LevelVO buildLevelVO(Long id, String levelName, String levelDesc,
                             List<LevelOption> options, String difficulty, Integer targetSalary) {
    LevelVO vo = new LevelVO();
    vo.setId(id);
    vo.setLevelName(levelName);
    vo.setLevelDesc(levelDesc);
    vo.setOptions(options.stream()
            .map(LevelOption::getOptionName)
            .collect(Collectors.toList()));
    vo.setDifficulty(difficulty);
    vo.setTargetSalary(targetSalary);
    return vo;
}
```

`generateLevel` 原来的 11 行 VO 组装被替换为一行 `return buildLevelVO(...)`。

### 4. Controller 接口（LevelController）

```java
@GetMapping("/hot")
public BaseResponse<List<HotLevelVO>> listHotLevels(
        @RequestParam(defaultValue = "10") int limit,
        @RequestParam(required = false) String direction) {
    return ResultUtils.success(levelService.listHotLevels(limit, direction));
}

@GetMapping("/{id}")
public BaseResponse<LevelVO> getLevelDetail(@PathVariable Long id) {
    return ResultUtils.success(levelService.getLevelDetail(id));
}
```

## 设计要点 / 注意事项

- **列名是驼峰不是下划线**：本项目 `map-underscore-to-camel-case: false`，表列名本身就是驼峰（`levelName`、`targetSalary`、`levelId`），自定义 SQL 里直接写驼峰列名即可，不能用下划线。
- **自定义 SQL 要手动过滤逻辑删除**：MyBatis-Plus 的 `isDelete` 自动过滤只对 `BaseMapper` 内置方法生效，手写 SQL 里必须自己加 `isDelete = 0`（`level` 和 `user_level` 两处都写了）。
- **详情接口不 try-catch**：让 `BusinessException` 冒泡到 `GlobalExceptionHandler`，`NOT_FOUND_ERROR` 才能正确返回 `40400`（若像 `generate` 那样 catch-all 会统一变 `50000`）。
- **limit 钳制 1~50**：防止前端传超大 limit 拖垮查询。
- **详情接口是配套必做的**：人气列表只返回摘要（不含 options），用户点进去作答前必须靠 `GET /level/{id}` 拿选项，所以本次一并实现。
