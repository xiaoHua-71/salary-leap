# 用户信息与密码修改

> 补齐用户模块里一直没记录的接口。登录/注册见 [03](03-登录注册模块.md)，
> BCrypt 加密原理见 [07](07-密码加密BCrypt改造.md)。

## 一、接口一览

| 接口 | 作用 | 备注 |
|------|------|------|
| `GET /user/current` | 获取当前登录用户（脱敏） | 返回 `UserVO`，不含密码 |
| `POST /user/update` | 更新当前登录用户信息 | 昵称 / 头像 / 方向标签，**只更新传了的字段** |
| `POST /user/updatePassword` | 修改当前登录用户密码 | 需校验旧密码 |
| `POST /user/logout` | 注销 | 清 session |

## 二、更新用户信息 `POST /user/update`

请求体 `UserUpdateRequest`（`nickname` / `avatar` / `direction`）。

关键点是**部分更新**：只对非空字段下 `set`，所以前端可以只传要改的那一项。

```java
User updateUser = new User();
updateUser.setId(userId);
if (StrUtil.isNotBlank(req.getNickname())) { updateUser.setNickname(...); }
if (StrUtil.isNotBlank(req.getAvatar()))   { updateUser.setAvatar(...); }
if (StrUtil.isNotBlank(req.getDirection())){ updateUser.setDirection(...); }
```

`direction`（方向标签）是 RAG 检索的输入 —— 出题时用它去知识库检索相关知识，
所以这个字段不只是个展示用的标签。

## 三、修改密码 `POST /user/updatePassword`

请求体 `UserPasswordUpdateRequest`：`oldPassword` + `newPassword`。

### 校验顺序

```
1. 旧密码、新密码都不能为空
2. 新密码长度 ≥ 8
3. passwordEncoder.matches(旧密码, 库里的密文)  ← BCrypt 校验，不是字符串比较
4. 通过 → 用 BCrypt 重新加密新密码并更新
```

**第 3 步是重点**：库里的密码是 BCrypt 哈希（每次加密盐值不同，同样的明文两次加密结果也不同），
所以**只能 `matches` 校验，不能拿明文和密文比** —— 详见 [07](07-密码加密BCrypt改造.md)。

### 一个容易漏的细节：改完密码要刷新登录态

```java
updateUser.setPassword(passwordEncoder.encode(newPassword));
this.updateById(updateUser);

// 刷新登录态，保持登录有效（无需重新登录）
request.getSession().setAttribute(USER_LOGIN_STATE, this.getById(loginUser.getId()));
```

session 里存的是一份 `User` 对象快照（其中含密码字段）。如果改完密码不刷新 session，
session 里留着的还是**旧密码的密文** —— 后续任何重新读取 session 用户、或拿它做比对的地方
都会用到过期数据。所以这里把数据库里的最新用户重新塞回 session。

### 为什么不用「验证码 / 邮箱」流程

当前实现要求提供旧密码。已经登录的用户如果**忘了旧密码**，走不了这个接口 ——
这是有意为之的简化（改密码属于敏感操作，只校验旧密码是最小实现）。
要做「忘记密码」得另开一条走邮箱验证码的流程（`sendCode` + 校验），目前没做。

## 四、注销 `POST /user/logout`

清掉 session 里的登录态。前端同时清掉本地的用户缓存即可。

## 五、文件清单

| 文件 | 作用 |
|------|------|
| `controller/UserController.java` | `/current`、`/update`、`/updatePassword`、`/logout` |
| `model/dto/user/UserUpdateRequest.java` | 更新用户信息请求体 |
| `model/dto/user/UserPasswordUpdateRequest.java` | 修改密码请求体 |
| `service/UserService.java` / `impl/UserServiceImpl.java` | `updateUser` / `updatePassword` |

## 六、验证要点

| 验证项 | 怎么验证 |
|--------|---------|
| 旧密码校验 | 传错旧密码 → 返回「旧密码错误」，密码不变 |
| 新密码长度 | 传 7 位新密码 → 返回「新密码长度不能小于8位」 |
| 改完仍在线 | 改密码成功后**不重新登录**，直接调 `GET /user/current` 应仍返回当前用户 |
| 新密码可登录 | 注销后用新密码登录成功，旧密码登录失败 |
| 部分更新 | 只传 `nickname` 调 `/user/update`，头像与方向标签应保持不变 |
