# 人气关卡模块（关卡池）

## 一、设计思路：统一「关卡池」

人气关卡不是独立功能，而是把 `Level` 表当成一个**关卡池**，三个写入源 + 一个读出口：

```
                ┌─────────────── Level 表（关卡池）───────────────┐
                │  id / levelName / levelDesc / options(含答案)     │
                │  difficulty / targetSalary / direction / priority │
                └──────▲──────────────────────▲───────────────────┘
                       │                      │
         PresetLevelStore                 AI generateLevel
         （预置兜底，priority=99）          （AI 生成，priority=0）
                       │                      │
                       └──────────┬───────────┘
                                  ▼
                      UserLevel 表（作答记录，levelId 外键）
                                  │
                                  ▼
                    人气关卡接口：按 levelId 统计作答次数 Top N
```

- **AI 生成**：现场出题，`priority = 0`（普通）
- **PresetLevelStore**：预置兜底题，`priority = 99`（推荐），落同一张表
- **人气关卡**：读接口，从 `UserLevel` 统计「用户使用最多的关卡」，复用 `priority` 做排序权重

三者共用一张 `Level` 表、同一个 `submitLevel` 出报告流程。预置关卡有 `id`，就能被作答、被统计、成为人气关卡，不用返工。

## 二、与 PresetLevelStore 的衔接

PresetLevelStore 不搞独立数据结构，直接产出 `Level` 实体落库，作为「种子数据加载器」：

```java
@Component
public class PresetLevelStore {

    public List<Level> loadAll() {
        // 手工维护的预置关卡，priority 打 99 标记为推荐
        // 返回的 Level 对象含 options(JSON，带 trueAnswer)
    }
}
```

落库时机（二选一）：

1. **启动时**：`ApplicationRunner` 扫描已存在的 `levelName`，缺失则插入（幂等）
2. **首次访问兜底时**：AI 失败降级时先查 `Level` 表有没有预置题，没有才加载

关键点：

- **幂等**：以 `levelName` 判断是否已存在，避免重复插入（或加唯一索引）
- **标记**：预置题 `priority = 99`，AI 题 `priority = 0`，不新增 `source` 字段，用 `priority` 区分即可
- **兜底复用**：AI 连续失败时，`fallbackLevel()` 直接从 `Level` 表按 `priority` 降序随机取一条预置题返回，天然衔接

## 三、数据模型

复用现有表，**不改表结构**：

| 表 | 字段 | 用途 |
|----|------|------|
| `Level.priority` | 0/99/999/9999 | 排序权重，预置题=99，人气 Top 可定时刷高 |
| `Level.direction` | 学习方向 | 人气关卡按方向筛选 |
| `UserLevel.levelId` | 外键 | 统计作答次数（热度） |

## 四、后端实现

### 文件清单

| 文件 | 作用 |
|------|------|
| `model/vo/HotLevelVO.java` | 人气关卡列表项（Level 摘要 + playCount） |
| `mapper/LevelMapper.java` | 加 `selectHotLevels` |
| `resources/mapper/LevelMapper.xml` | 人气统计 SQL + resultMap |
| `service/LevelService.java` | 加 `listHotLevels` / `getLevelDetail` |
| `service/impl/LevelServiceImpl.java` | 实现列表 + 详情（详情复用脱敏逻辑） |
| `controller/LevelController.java` | 加 `GET /level/hot`、`GET /level/{id}` |
| `config/PresetLevelStore.java` | 预置题库加载器 |

### 关键 SQL（LevelMapper.xml）

用子查询统计作答次数，避免 `ONLY_FULL_GROUP_BY` 坑；数据量大时可改为 `JOIN + GROUP BY`：

```sql
<select id="selectHotLevels" resultMap="HotLevelResultMap">
    SELECT l.*,
           (SELECT COUNT(*) FROM user_level ul
             WHERE ul.level_id = l.id AND ul.is_delete = 0) AS play_count
    FROM level l
    WHERE l.is_delete = 0
    <if test="direction != null and direction != ''">
        AND l.direction = #{direction}
    </if>
    ORDER BY play_count DESC, l.priority DESC, l.id DESC
    LIMIT #{limit}
</select>
```

### HotLevelVO

```java
@Data
public class HotLevelVO {
    private Long id;           // 关卡 id
    private String levelName;  // 关卡名称
    private String levelDesc;  // 需求描述
    private String difficulty; // 难度（简单/中等/困难）
    private Integer targetSalary; // 目标薪资
    private String direction;  // 学习方向
    private Integer playCount; // 作答次数（热度）
    private Integer priority;  // 优先级
}
```

### 详情接口复用脱敏逻辑

`getLevelDetail(id)` 从 `Level` 表取出完整 `options`（含答案），反序列化后只抽 `optionName` 返回，逻辑与 `generateLevel` 的脱敏一致（`LevelServiceImpl.java:80-83`）。

## 五、前端接口文档

> 通用约定：
> - Base 前缀：所有接口前缀为 `/api`
> - 统一响应体：`{ "code": 0, "data": ..., "message": "ok" }`，`code = 0` 表示成功
> - **`id` 字段类型为字符串**（后端 Long，序列化时转 string，防 JS 精度丢失）
> - 错误码：`40000` 参数错误 / `40100` 未登录 / `40400` 数据不存在 / `50000` 系统异常

### 1. 人气关卡列表

浏览热门关卡，**无需登录**。

**请求**

```
GET /api/level/hot
```

Query 参数：

| 参数 | 类型 | 必填 | 默认 | 说明 |
|------|------|------|------|------|
| limit | int | 否 | 10 | 返回数量（1~50） |
| direction | string | 否 | 无 | 学习方向筛选，如「Java后端开发」「前端开发」 |

**响应**：`BaseResponse<List<HotLevelVO>>`

```json
{
  "code": 0,
  "message": "ok",
  "data": [
    {
      "id": "1001",
      "levelName": "电商秒杀库存扣减",
      "levelDesc": "设计一个高并发秒杀场景下的库存扣减方案…",
      "difficulty": "中等",
      "targetSalary": 18000,
      "direction": "Java后端开发",
      "playCount": 342,
      "priority": 999
    },
    {
      "id": "1002",
      "levelName": "前端首屏性能优化",
      "levelDesc": "针对首屏加载慢的问题给出优化方案…",
      "difficulty": "简单",
      "targetSalary": 12000,
      "direction": "前端开发",
      "playCount": 201,
      "priority": 99
    }
  ]
}
```

字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 关卡 id，点进详情用 |
| levelName | string | 关卡名称 |
| levelDesc | string | 需求描述 |
| difficulty | string | 难度：简单 / 中等 / 困难 |
| targetSalary | number | 目标薪资（元/月） |
| direction | string | 学习方向 |
| playCount | number | 作答次数，越大越靠前 |
| priority | number | 优先级（0 普通 / 99 推荐 / 999 精选 / 9999 置顶） |

### 2. 关卡详情（作答页）

用户点进某个人气关卡后，获取完整题目（**选项不含答案**），**无需登录**。

**请求**

```
GET /api/level/{id}
```

Path 参数：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | long | 是 | 关卡 id（来自人气列表的 id） |

**响应**：`BaseResponse<LevelVO>`

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": "1001",
    "levelName": "电商秒杀库存扣减",
    "levelDesc": "设计一个高并发秒杀场景下的库存扣减方案…",
    "options": ["Redis 预扣减", "数据库乐观锁", "直接扣数据库", "消息队列削峰"],
    "difficulty": "中等",
    "targetSalary": 18000
  }
}
```

字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 关卡 id |
| levelName | string | 关卡名称 |
| levelDesc | string | 需求描述 |
| options | string[] | 选项名称列表（**不含答案**） |
| difficulty | string | 难度 |
| targetSalary | number | 目标薪资 |

> `40400`：关卡不存在（id 无效或已删除）

### 3. 提交作答（复用现有接口）

用户选完选项后提交，**需登录**。

**请求**

```
POST /api/level/submit
Content-Type: application/json
```

请求体：

```json
{
  "levelId": "1001",
  "userOptions": ["Redis 预扣减", "消息队列削峰"]
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| levelId | long | 是 | 关卡 id |
| userOptions | string[] | 是 | 用户选择的选项名称（非空） |

**响应**：`BaseResponse<ReportVO>`（报告内容，含得分/评价/薪资变化等，见 `08-作答报告模块.md`）

## 六、后续可扩展

- **定时刷热度**：定时任务把人气 Top N 的 `priority` 刷成 999，让热题在列表更靠前
- **分页**：人气列表目前 `limit` 控制，量大后可接 `PageRequest` 分页
- **方向 + 难度组合筛选**：`direction` 已有，可加 `difficulty` 参数
